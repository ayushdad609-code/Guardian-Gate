# AI Safety Layer

This skill provides a deterministic safety boundary for AI operations. It ensures that every command or database mutation planned by an AI agent is first validated against a strict security policy and logged for human auditing.

## Workflow

1.  **Plan Actions**: The AI agent describes its intended plan.
2.  **Dry-Run / Safety Check**: Use the `safety_check.py` script to validate the plan.
    - If a violation is found, the script exits with an error and blocks execution.
    - If passed, the action is logged to `ai_safety_audit.log`.
3.  **Human Review (Optional but Recommended)**: For high-stakes operations, the user can review the audit log before final approval.
4.  **Execute**: Proceed with execution only after the safety check returns success.

## Tools & Scripts

- **`scripts/safety_check.py`**: Validates commands against a regex-based blacklist.
  - **Usage**: `python scripts/safety_check.py "<commands_to_check>"`
  - **Audit Log**: Every check (passed or blocked) is appended to `ai_safety_audit.log` with a timestamp.

## Safety Policies

The following patterns are currently blocked by default:
- Destructive deletions (e.g., `rm -rf /`)
- Database schema deletions (e.g., `DROP TABLE`)
- Bulk data deletions without filters (e.g., `DELETE FROM table`)
- System-level destructive commands (`mkfs`, `shred`, `shutdown`, `reboot`)
- Critical permission changes (e.g., `chmod 777 /`)

## Best Practices

- **Zero-Trust**: Always run the safety check before executing any bash command or database script generated by an AI.
- **Traceability**: Maintain the `ai_safety_audit.log` as a "Black Box" recorder for AI behavior.
- **Continuous Refinement**: Update the `BLOCKED_PATTERNS` in `scripts/safety_check.py` as new edge cases or risks are identified in your specific environment.
